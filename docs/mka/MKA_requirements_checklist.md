## 1) Низкополигональные модели (Приложение 1)

### 1.1 Форматы и общий состав
1. Формат модели: `FBX 7.4 (FBX2014)`, бинарный.
2. Передача: один `ZIP` до 1 ГБ.
3. Состав архива: от 2 до 21 `FBX`:
4. `1 FBX` благоустройства.
5. До `20 FBX` для ОКС.
6. Все ОКС и благоустройство АГР обязательны к включению.
7. Нереконструируемые существующие здания в границах участка не моделируются.

### 1.2 Ограничения геометрии
1. Лимит треугольников для одного `FBX` ОКС (включая эксплуатируемую кровлю): `до 150 000`.
2. Лимит для благоустройства + его элементы + растительность (суммарно): `до 180 000`.
3. Периметр геометрии благоустройства: выдавливание вниз не менее `1 м`.
4. Геометрия должна быть триангулирована перед экспортом.
5. Трансформации должны быть применены (reset/apply).
6. Иерархические связи/группы между объектами запрещены.
7. Нормали видимых полигонов должны смотреть на наблюдателя.
8. Не допускаются изолированные вершины/рёбра/полигоны и нулевые рёбра.

### 1.3 Материалы и текстуры
1. Допустимые шейдеры: `Standard (Legacy)`, `Physical Material`, `Principled BSDF`.
2. Сторонние рендер-движки (`VRay`, `Octane`, `Corona`, `Arnold`) запрещены.
3. Полупрозрачные материалы:
4. Текстуры для них запрещены.
5. Прозрачность фиксируется на `50%`.
6. Материалов полупрозрачных деталей: не более `7`.
7. Текстуры: атласы в `PNG`, встроенные в `FBX` (для low-poly).
8. Размеры текстур: только `256`, `512`, `1024`, `2048` px.
9. Вес одной текстуры: до `3 МБ`.
10. Padding между UV-островами: не менее `8 px` (если острова с уникальными изображениями рядом).
11. Обязательная карта: `diffuse`.
12. Дополнительные: `normal`, `transparency`, `roughness`, `metalness`.
13. `roughness` и `metalness` применяются только парой.
14. В одном текстурном наборе все карты одного размера (кроме заглушек).
15. На 1 ОКС: 1 текстурный набор, при эксплуатируемой кровле допускается второй.
16. Для всех элементов благоустройства: 1 набор до `512x512`.
17. Для растительности: 1 набор до `2048x2048`, только `diffuse` и опционально `transparency`.

### 1.4 Плотность текстур (low-poly)
1. Применяется только к поверхностям рельефа благоустройства.
2. Диапазон: `10-40 px/m`.
3. Для полигонов, выдавленных вниз по периметру, а также для ОКС/растительности/элементов благоустройства это требование не применяется.

### 1.5 Координаты и именование (low-poly)
1. Единицы измерения: метрические (`1 unit = 1 m`).
2. Координатная привязка: МСК Москвы, условные системы запрещены.
3. Имена: только латиница, цифры, `_`, без пробелов.
4. Максимальная длина имени: `254` символа.
5. Базовые суффиксы: `_Main`, `_MainGlass`, `_Ground`, `_GroundGlass`, `_GroundEl`, `_GroundElGlass`, `_Flora`.
6. Суффиксы карт: `_d`, `_n`, `_o`, `_m`, `_r`.
7. Для `Address` используется нормализованная строка адреса/кадастра по маске требований.

## 2) Высокополигональные модели (Приложение 2)

### 2.1 Форматы и состав
1. Формат модели: `FBX 7.4 (FBX2014)`, бинарный.
2. Для ОКС: `ZIP` до `500 МБ`.
3. Для благоустройства: `ZIP` до `1 ГБ`.
4. В архиве: `FBX` модели, опционально `FBX` освещения, `GeoJSON`, от `3` до `2100` файлов `PNG`.
5. Каждый отдельностоящий ОКС оформляется отдельной моделью.
6. Файл благоустройства (без эксплуатируемой кровли ОКС) обязателен и подаётся отдельно.

### 2.2 Ограничения геометрии
1. Лимит треугольников для одного `FBX` ОКС (без коллизии): `до 1 000 000`.
2. Лимит треугольников для благоустройства (без коллизии) зависит от площади `(Sтер - Sпз)`:
3. До `0.05 га`: `до 300 000`.
4. `0.05-0.1 га`: `до 705 000`.
5. `0.1-0.25 га`: `до 1 125 000`.
6. `0.25-0.5 га`: `до 1 650 000`.
7. `0.5-0.75 га`: `до 1 950 000`.
8. `0.75-1.0 га`: `до 2 625 000`.
9. `1.0-1.5 га`: `до 3 150 000`.
10. Более `1.5 га`: `до 4 500 000`.
11. Геометрия триангулируется перед экспортом.
12. Все трансформации (включая коллизии) применяются.
13. Периметры ОКС и благоустройства выдавливаются вниз минимум на `1 м`.

### 2.3 Материалы и текстуры (high-poly)
1. Допустимые шейдеры: `Standard (Legacy)`, `Physical Material`, `Principled BSDF`.
2. Сторонние рендер-движки запрещены.
3. Пути к текстурам в материалах должны быть удалены.
4. Макс. материалов на объект геометрии: `7`.
5. Если для `Main/Ground` требуется более `100 UDIM`, вводятся дополнительные материалы (до 7).
6. Текстуры не встраиваются в `FBX`; передаются отдельными `PNG`.
7. Разрешения только `2048x2048` и `4096x4096`.
8. Обязательные карты: `Diffuse`, `ERM`, `Normal`.
9. Прозрачность при необходимости кодируется в alpha канале `Diffuse`.
10. Для `ERM` и `Normal` альфа-канал запрещён.
11. Карты нормалей должны быть подготовлены под `DirectX`.
12. Каждая текстура архива должна использоваться хотя бы одним полигоном.
13. Паддинг: от `16 px` (2048) и от `32 px` (4096).

### 2.4 UV/UDIM
1. Для `Main` и `Ground`: UV строго по `UDIM`, один набор/канал.
2. UDIM плитки заполняются строго последовательно с `1001`, без пропусков.
3. Зеркалить UV-острова для UDIM нельзя.
4. Для `MainGlass/GroundGlass`: UV в пределах плитки `1001`, допускается overlap островов.
5. Текстурные заглушки:
6. Размер `256x256`.
7. Без альфа-канала.
8. Один усреднённый цвет.

### 2.5 Коллизии
1. Коллизии именуются с префиксом `UCX_`.
2. Объекты коллизии должны быть выпуклые, замкнутые, без отверстий.
3. Коллизии обязательны для ОКС, существующих ОКС (если попадают в границы), и геометрии благоустройства (без МАФ/освещения/растительности).
4. Для козырьков/заборов/ограждений толщиной до `5 см` коллизии не строятся.
5. Каждый `FBX` (кроме файла освещения) должен иметь свою коллизию.
6. Коллизии не должны пересекаться; рекомендованный зазор `0.02-1 см`.
7. Допуск отклонения коллизии:
8. Благоустройство: до `10 см`.
9. Нижние доступные зоны ОКС: до `30 см`.
10. Остальная геометрия ОКС: до `1 м`.
11. Лимит треугольников коллизии:
12. Для моделей `< 50 000` треугольников: до `15 000`.
13. Для остальных: `Pmax = Nmodel * 0.05`, с округлением вверх.
14. Дополнительно указано: при достижении лимита модели коллизия может добавлять до `100 000` треугольников.

### 2.6 Стекло и освещение
1. Стекло обязательно моделируется при наличии.
2. Все стеклянные элементы одной модели объединяются в отдельный объект.
3. Текстуры в материале стекла запрещены.
4. Разных стеклянных материалов: не более `7`.
5. Для односторонне наблюдаемых окон стекло делается плоской поверхностью (без толщины).
6. Освещение подаётся отдельным `FBX`, максимум `250` источников.
7. Допустимые типы источников: `Omni` и `Spot`.
8. Мин. расстояние между источниками:
9. `Omni`: `5 м`.
10. `Spot`: `1.5 м`.
11. Цвет и интенсивность источников обязательны к настройке.
12. Источники освещения должны быть привязаны к корневому `Root`-объекту.

### 2.7 Координаты и именование (high-poly)
1. Позиционирование и плановый поворот строго по проекту.
2. После применения трансформаций углы поворота объектов: `0 градусов`.
3. Pivot объекта в мировых координатах редактора должен быть в нуле по осям.
4. Точка отсчета модели должна совпадать с проектной (включая отметку по оси `Z`).
5. Внутри одного `FBX` точки отсчета связанных моделей должны совпадать.
6. Имена: латиница, цифры, `_`, без пробелов, до `254` символов.
7. Суффиксы/префиксы: `SM_`, `T_`, `M_`, `_Main`, `_MainGlass`, `_Ground`, `_GroundGlass`, `_Light`, `_Root`, `_Omni`, `_Spot`, `UCX_`, `NumberUDIM`, `SlotNumber`.

## 3) GeoJSON (Приложение 3)

### 3.1 Общие правила
1. GeoJSON обязателен для high-poly архива.
2. Заполнение строго по утвержденной схеме полей.
3. Допустимо менять только значения полей, но не структуру и названия.
4. Кодировка файла: `UTF-8`.

### 3.2 Ключевые поля
1. Обязательные поля по объекту ОКС: `address`, `okrug`, `rajon`, `name`, `developer`, `designer`, `cadNum`, `FNO_code`, `FNO_name`, `ZU_area`, `h_relief`, `h_otn`, `h_abs`, `s_obsh`, `s_naz`, `s_podz`, `spp_gns`, `act_AGR`, `imageBase64`, `coordinates`, `Glasses` (при наличии стекла), `other` (может быть пустым).
2. `coordinates`: точка вставки в МСК-77, точность до 3 знаков после точки.
3. Максимально допустимое смещение координат от планового положения: `0.5 м`.
4. `imageBase64`: исходный `jpg 256x256`, далее конвертация в base64.
5. Для `Glasses` описываются параметры материалов стекла (`color RGB`, `transparency`, `refraction`, `roughness`, `metallicity`) для каждого `MainGlass/GroundGlass` материала до 7.

## 4) Быстрый предсдачный контроль

1. Проверить, что low-poly и high-poly версии отражают одинаковый состав проекта АГР.
2. Проверить лимиты полигонов по типу модели и площади.
3. Проверить структуру архива и состав файлов (`FBX`/`Light`/`GeoJSON`/`PNG`).
4. Проверить нейминг по маскам и суффиксам.
5. Проверить UV/UDIM, паддинги и типы текстур.
6. Проверить стекло и освещение по ограничениям.
7. Проверить обязательные поля GeoJSON и координаты точки вставки.
8. Проверить отсутствие запрещенных сущностей: пустых объектов, лишних сценовых элементов, сторонних шейдеров/движков.
