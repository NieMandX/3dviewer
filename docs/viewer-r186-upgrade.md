# Viewer 0.97: Three.js r186, загрузка и Env

Дата: 03.10.2026. База сравнения — Viewer 0.96, commit `c8663f3`, Three.js
0.184.0. Этот выпуск предназначен для GitHub Pages; `agr.vision` и Yandex
Object Storage отдельно не обновляются.

## Что даёт r186

Переход включает изменения r185 и r186. Для текущего Viewer основной выигрыш —
исправления WebGPU и снижение объёма собственного кода совместимости.

- В ключе GPU pipeline учитывается polygon offset. Удалена локальная заплатка
  `depth-bias-cache.js`; переключение приоритета материала проверяется по
  пикселям в настоящем WebGPU и классическом WebGL. Геометрия и depth test
  сохраняются. [Изменение Three.js](https://github.com/mrdoob/three.js/pull/34406).
- Исправлены ссылки на освобождённые текстуры и обновление bind groups.
  Это полезно при смене материалов и моделей, но не заменяет освобождение
  ресурсов самим Viewer. [r185](https://github.com/mrdoob/three.js/pull/33680),
  [r186](https://github.com/mrdoob/three.js/pull/34276).
- Повторное использование render pass descriptors уменьшает временные
  аллокации. Ускорение нашего Viewer этим тестированием не установлено.
  [Изменение Three.js](https://github.com/mrdoob/three.js/pull/33525).

Новые SunLight/каскадные тени, LightProbeGrid, небо с облаками и GaussianSplat
дают возможности для следующих отдельных функций. Они не включаются сами
от обновления движка. Для архитектурного Viewer следующий полезный эксперимент —
каскадные тени на большом участке, затем запечённое непрямое освещение.
Gaussian splats требуют отдельного пути импорта и отображения; наш классический
WebGLRenderer не получает их автоматически.
[r185](https://github.com/mrdoob/three.js/releases/tag/r185),
[r186](https://github.com/mrdoob/three.js/releases/tag/r186).

## Изменения совместимости

Core, WebGPU, TSL, addons, FBX worker и Draco зафиксированы на **0.186.0**.
`PCFSoftShadowMap` заменён на `PCFShadowMap`: первый удалён из WebGPURenderer,
а PCF в нём теперь использует мягкую фильтрацию. Общая панель настроек теней
соответствует доступным режимам.
[Migration Guide](https://github.com/mrdoob/three.js/wiki/Migration-Guide).

Освобождение WebGPURenderer в r186 асинхронное. Renderer, SceneCore и Viewer
теперь возвращают одну и ту же Promise при повторном dispose. Canvas и
обработчики отключаются сразу; освобождение backend ждёт окончания текущей
инициализации. Если init завершился ошибкой, очищается частично созданный
backend без повторного init из `setAnimationLoop`.

Сохранены demand-driven рендер, существующие обходы для HDRI/миниатюр,
контракт `_origMaterial`, координаты и отдельный импорт GLB. Новые визуальные
эффекты в этот выпуск не добавлялись.

## Загрузка с сервера

Для приватного файла сначала получается временная ссылка через Storage SDK,
затем потоковое скачивание показывает реальные байты и процент:
`42% · 84 из 200 МБ`. При неизвестном размере показываются полученные байты.
HTTP-сжатие учитывается; 100% означает окончание скачивания, после чего
появляется отдельный этап «Обработка модели».

Смена комнаты отменяет чтение потока; устаревший прогресс и результат импорта
не попадают в новую комнату. Ошибка скачивания имеет видимый статус.
Файл по-прежнему собирается в памяти браузера до импорта: это не потоковый
парсер FBX/ZIP/GLB и не устранение пиков памяти больших загрузок.

## Категория Env

| Вход | Категория |
|---|---|
| Отдельный FBX или GLB, включая имя `SM_…` | Env |
| ZIP с прежним числовым префиксом | НПМ |
| ZIP с префиксом `SM…` | ВПМ |
| Остальной ZIP с GeoJSON | ВПМ |
| Остальной ZIP без GeoJSON | Env |

Имя распознаваемого пакета имеет приоритет: отсутствие GeoJSON в ВПМ не должно
скрывать неполноту пакета переводом в Env. НПМ не обязан содержать GeoJSON.
Категория описывает путь импорта, а не заключение о соответствии требованиям.

Кнопка Env скрывает/показывает корни моделей целиком, сохраняя состояние
отдельных объектов и материалов, в том числе скрытых коллизий. Она независима
от НПМ/ВПМ и согласована с кнопкой глаза файла. В режиме входа в комнату
скрыта вместе с остальными переключателями содержимого.

## Проверка и измерения

На macOS в Chrome с аппаратным WebGPU и с `?renderer=webgl` сравнены реальные
FBX (22,7 МБ), GLB (6,7 МБ), НПМ ZIP (15,3 МБ), ВПМ ZIP (2,9 МБ):
8 импортов для каждой версии. Совпали число моделей, мешей, треугольников,
материалов, текстур, границы и положение камеры. Ошибок импорта/рендера нет.
Существующие предупреждения FBX о неподдерживаемых свойствах материалов
сохранены. Выполнено визуальное сравнение выбранных пар кадров.

Дополнительно в WebGPU обе версии импортировали GLB 501 МБ:
15 753 277 треугольников, 220 мешей, 164 материала, 364 текстуры.
Состав, границы и камера совпали, после dispose записи моделей отсоединены.
Это не измерение возврата всей GPU-памяти драйверу.

Диагностические замеры 30 прогретых кадров на четырёх небольших сценах:

| Сцена | WebGPU r184/r186, медиана мс | WebGL r184/r186, медиана мс |
|---|---:|---:|
| FBX | 3,0 / 3,2 | 0,6 / 0,6 |
| GLB | 2,4 / 2,8 | 0,3 / 0,4 |
| НПМ | 2,1 / 2,6 | 0,2 / 0,2 |
| ВПМ | 2,2 / 2,3 | 0,4 / 0,4 |

Между кадрами ожидалось завершение GPU-очереди/WebGL. Это короткие замеры одного
компьютера, а не устойчивый FPS benchmark: **доказанного ускорения нет**.
На большой сцене с водой медиана практически одинакова (56,2/56,3 мс),
но анимация не была изолирована, поэтому этот результат не служит сравнительным
benchmark. Холодный импорт также не показал устойчивого выигрыша.

Автоматические проверки покрывают потоковые загрузки с известным/неизвестным
размером, сжатие, отмену, сетевую ошибку, загрузку из комнаты по временной
ссылке, смену проекта во время загрузки, worker и fallback ZIP, Env,
приоритет глубины, асинхронную очистку, существующие lifecycle и material tests.
Проверена компоновка на ширинах 390, 768 и 1280 px без горизонтального переполнения.
Тест Storage использует подмену API и настоящий локальный HTTP-поток; доступ
к приватному production storage этим не подтверждается.

Физический iPad/iPhone не проверен. Обновление само по себе не уменьшает DPR,
размер теней, текстур или стоимость воды и стекла. Для мобильного профиля нужны
отдельные замеры на устройстве и настройка этих бюджетов.
